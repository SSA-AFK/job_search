# Company Search Web Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a locally runnable FastAPI and React application that searches versioned company seed data without Redis, Celery, an LLM, or external network access.

**Architecture:** FastAPI exposes versioned query endpoints backed by SQLAlchemy repositories and services. Alembic owns the normalized schema, a deterministic importer owns seed data, and the React SPA treats URL search parameters as the source of UI state. Collection endpoints exist in a deliberately unavailable state so the second plan can activate them without changing the public contract.

**Tech Stack:** Python 3.12+, FastAPI, Pydantic 2, SQLAlchemy 2.x, Alembic, SQLite, pytest, React, TypeScript, Vite, Vitest, Testing Library, Playwright

## Global Constraints

- API prefix is `/api/v1`; JSON fields use `snake_case`; timestamps are UTC RFC 3339.
- Stage one must run without Redis, Celery, LLM credentials, or external network access.
- Search supports name/alias query plus industry, sub-industry, funding stage, scale, city, pagination, and sorting.
- Source platform, raw id, and apply URL remain related through `job_sources`; do not replace them with parallel JSON arrays.
- Seed import is idempotent and all UUID values are generated by the application.
- External URLs accept only HTTP(S); API and logs never expose secrets, stack traces, or unclean third-party HTML.
- `collection-requests` returns `503 collection_unavailable` until the ingestion plan activates it.
- Make each commit only after the task's focused tests and the relevant broader suite pass.

- [ ] **Step 3: Implement models and the initial migration**

Use SQLAlchemy 2.x `Mapped` declarations and a reusable GUID `TypeDecorator` that stores native PostgreSQL UUID later and 36-character strings on SQLite. Represent JSON fields with SQLAlchemy `JSON`; use named unique constraints exactly as specified in the design.

```python
class JobSource(Base):
    __tablename__ = "job_sources"
    __table_args__ = (
        UniqueConstraint("provider", "source_raw_id", name="uq_job_source_provider_raw_id"),
    )

    id: Mapped[UUID] = mapped_column(GUID(), primary_key=True, default=uuid4)
    job_posting_id: Mapped[UUID] = mapped_column(ForeignKey("job_postings.id", ondelete="CASCADE"))
    provider: Mapped[str] = mapped_column(String(50))
    source_raw_id: Mapped[str] = mapped_column(String(255))
    apply_url: Mapped[str] = mapped_column(String(2000))
    first_seen_at: Mapped[datetime]
    last_seen_at: Mapped[datetime]
    is_active: Mapped[bool] = mapped_column(default=True)
```

`JobSource` intentionally does not inherit `TimestampMixin`: `first_seen_at` and `last_seen_at` are its lifecycle timestamps and the approved design does not define redundant `created_at` or `updated_at` fields for this table.

The migration must create indexes for company filter columns, normalized name/alias, `job_postings(company_id, is_active)`, and collection status/query lookup.

## Stage-One Completion Gate

Do not begin the ingestion plan until:

- The stage-one complete verification commands pass from a clean local database.
- The UI can search seeded data and open a company/job source without external services.
- Repeated seed import leaves row counts stable.
- The collection endpoint returns the documented `503` error envelope.
- No real credentials, generated database, virtual environment, or frontend build output are tracked.
