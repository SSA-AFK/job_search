# Excel 公司名单 JSON 转换工具设计

日期：2026-08-13

## 目标

在现有 Python 后端中新增一个命令行工具。用户可一次传入一份或多份 Excel，也可在不同时间分多次运行。工具从 Excel 提取公司名称与统一社会信用代码，将本次首次出现且历史未导入的公司写入结构化 JSON。

## 使用方式

命令接受一个或多个 `.xlsx` 文件路径：

```powershell
cd backend
uv run python -m app.imports.company_excel_to_json "第一份.xlsx" "第二份.xlsx"
```

默认在当前目录生成本次新增公司 JSON。命令提供可选参数指定输出文件和持久化历史索引文件，以便脚本、定时任务或不同目录复用同一份导入历史。

## 输入识别

- 逐个处理命令中列出的工作簿，文件顺序即优先顺序。
- 在每个工作簿中按工作表顺序查找表头行；表头行必须同时包含“公司名称”和“统一社会信用代码”。
- 不写死工作表名、表头行号或列号，以兼容天眼查导出格式的合理变化。
- 一个工作簿中若有多个满足条件的工作表，则依工作表顺序处理全部匹配工作表。
- 不满足 `.xlsx` 格式、无法读取或完全找不到所需表头时，该次导入失败，历史索引与输出文件均不更新。

## 清洗与有效性规则

- 公司名称去除首尾空白；空名称直接跳过。
- 统一社会信用代码转为字符串，去除首尾及内部空白并转换为大写。
- 空值、仅含空白或 `-` 的统一社会信用代码直接跳过。
- 统一社会信用代码作为标识符保存为 JSON 字符串，不进行数值转换。
- 本工具只依据统一社会信用代码去重，不因公司名称相同而合并，也不负责联网校验代码真伪。

## 去重规则

工具使用同一个标准化后的统一社会信用代码完成三层去重：

1. 同一工作表内重复：保留首次出现的记录。
2. 同一次命令的多个工作表或多个 Excel 之间重复：按输入文件及工作表顺序保留首次出现的记录。
3. 不同运行之间重复：若代码已存在于持久化历史索引中，则跳过该公司。

如果同一信用代码对应不同公司名称，仍视为同一家公司，保留首次成功导入时的公司名称。后续名称不会覆盖历史记录。

## 输出格式

每次运行只输出本次新增公司，顶层为纯 JSON 数组：

```json
[
  {
    "company_name": "示例公司",
    "unified_social_credit_code": "91110000XXXXXXXXXX"
  }
]
```

- 文件编码为 UTF-8，中文不转义，缩进为 2 个空格。
- 没有新增公司时仍成功生成 `[]`。
- 输出顺序与首次遇到各有效信用代码的顺序一致。

## 持久化历史

- 使用独立的 JSON 历史索引文件，保存所有已成功导出的信用代码及其首次导入的公司名称。
- 默认历史索引放在后端项目的本地数据目录中，并加入 `.gitignore`，避免将业务数据提交到版本库。
- 可通过命令行参数指定历史索引路径。只要多次运行使用同一个索引文件，即可跨目录、跨时间去重。
- 历史索引仅在所有 Excel 均成功解析且本次输出成功写入后更新。
- 输出文件与历史索引均采用临时文件写入后原子替换，避免进程中断留下半写文件。
- 更新历史索引前使用进程级文件锁，锁内重新读取索引并再次去重，避免两个工具进程同时运行时重复导出同一公司。

## 组件边界

- `reader`：定位表头并从工作簿产生原始公司记录。
- `normalizer`：清洗名称与信用代码，过滤无效行。
- `history store`：读取、锁定并原子更新历史索引。
- `import service`：按稳定顺序完成批内及历史去重，形成新增公司列表。
- `CLI`：解析路径与选项、调用服务、写出 JSON，并输出简短统计信息到终端。

核心转换逻辑与命令行解析分离，便于单元测试及未来被 API 复用。

## 错误处理与一致性

- 输入文件不存在、扩展名错误、工作簿损坏、缺少目标列或历史索引格式损坏时，以非零退出码失败并给出具体文件与原因。
- 任一输入失败即整批失败，不输出部分结果，也不把任何信用代码写入历史。
- 输出路径不可写时，历史不更新。
- 历史锁获取失败或超时则明确失败，不绕过去重保护。
- 已存在的目标输出文件只有在本次结果完整生成后才会被替换。

## 测试与验收

自动化测试覆盖：

- 天眼查样式的第 2 行表头以及表头位置变化。
- 信用代码为空、空白或 `-` 的行被跳过。
- 信用代码大小写和空白标准化。
- 同一文件、多个文件、不同运行之间的去重。
- 同代码不同名称时保留首次导入名称。
- 无新增公司时输出 `[]`。
- 缺列、损坏文件或损坏历史导致整批失败且历史不变。
- 两个并发导入使用同一历史索引时不会重复导出。

最后使用用户提供的真实天眼查 Excel 执行一次转换，核对输出对象字段、非空信用代码、信用代码唯一性和 JSON 可重新解析性。再复制一份输入进行同批去重验证，并在第二次运行中验证输出为 `[]`。

## 非目标

- 不修改原始 Excel。
- 不按公司名称去重。
- 不联网补全或验证公司信息。
- 不提供网页上传界面或数据库存储；这些可在核心转换服务稳定后另行扩展。
