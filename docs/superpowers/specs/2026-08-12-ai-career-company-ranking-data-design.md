# AI 求职公司榜精简数据设计

日期：2026-08-12

状态：已确认，待书面评审
适用范围：首版 AI 行业公司公共观察榜

## 1. 产品目标

榜单服务于打算进入 AI 行业的求职者，回答一个核心问题：**哪家公司更值得长期加入**。

首版不使用招聘职位、招聘数量、薪资和岗位变化数据。所有用户看到同一行业榜单。大型成熟公司和高成长创业公司进入同一榜单，但评分按发展阶段校准，避免资产规模天然决定名次。

榜单不是投资建议，也不评价具体岗位、团队或直属管理者。它衡量的是公司层面的长期职业价值。

## 2. 数据原则

1. 只采集能改变求职判断的字段。
2. 本地 Excel 是首批 100 家的内部基线缓存；天眼 AI 只补充表中缺失或需要更新的结构化数据，天眼评分本身不使用。
3. 用户可见结论必须有允许展示的独立公开证据。供应商原始字段、原文和内部中间值不公开。
4. 缺失信息不等于负面信息；缺证据的指标记为未知，不直接记零。
5. 法定代表人、联系方式、个人关系、详细地址等个人或低相关数据不采集。
6. 优先比较近三年新增与变化，不用历史累计绝对量简单奖励大公司。

## 3. 精简字段集

### 3.1 企业与阶段锚点

仅内部保存：

- 企业唯一标识、统一社会信用代码哈希、企业全称。
- 成立时间、经营状态、企业规模或人员规模分档。
- 融资阶段、上市状态。
- 发展阶段：成熟型、成长期、早期。

用途：实体去重、入榜资格和阶段校准，不单独形成高分。

### 3.2 AI 核心性与产品壁垒

保留：

- AI 是否属于核心业务，而非仅在经营范围中出现。
- AI 赛道，如基础模型、AI 基础设施、智能驾驶、机器人、行业 AI。
- 代表性 AI 产品或平台。
- 近三年 AI 相关发明专利新增。
- 近三年 AI 相关软件著作权新增。

数据来源：官网、官方产品页、政府备案为主；天眼 AI 的专利和软著用于检索与交叉验证。

### 3.3 商业与市场验证

保留：

- 近三年公开中标或采购结果。
- 官网或政府来源可验证的代表性客户案例。
- 产品商业化、正式上线或规模化落地事件。
- 与主营 AI 业务直接相关的资质。

不使用合同金额绝对值直接比较，避免政府项目型企业和大型公司获得结构性优势。

### 3.4 成长动能

保留：

- 近三年融资事件及轮次变化。
- 产业资本或重要机构股东进入。
- 与业务扩张相关的分支机构变化。
- 上市、并购、增资等重大成长事件。

不保存全部工商变更流水，只保存事件类型、日期、方向和证据引用。

### 3.5 行业地位

保留：

- 国家级或省级高新、专精特新等有效资质。
- AI 相关标准制定参与。
- 权威政府或行业组织发布的奖项、名单和备案。
- 可验证的技术影响事件。

商标总量、普通奖项和付费榜单不计分。

### 3.6 经营稳定性底线

保留：

- 经营异常状态。
- 严重违法失信。
- 重大行政处罚。
- 被执行或失信被执行概况。
- 破产、清算或经营状态恶化。

普通民事纠纷数量不直接扣分。风险信息必须结合严重度、时间和是否解除，避免“大公司案件多”造成机械惩罚。

## 4. 每家公司按缺口调用 3–4 类天眼 API

Excel 已提供公司名称、经营状态、成立日期、企业规模、注册资本、参保人数、行业、省市、经营范围和统一社会信用代码，因此不再调用企业综合画像、实体搜索或完整历史趋势接口。

采用“最多四类概要调用 + 返回字段投影”，不遍历全部明细接口：

1. **融资与关键成长事件**：融资、重要股东进入、增资、上市及并购事件。
2. **知识产权汇总**：近三年专利和软件著作权；在本地按 AI 关键词及分类过滤。
3. **经营验证汇总**：近三年招投标、中标、资质和重要公告。
4. **经营风险概要**：异常、处罚、执行、失信、破产清算。

调用按缺口执行：某个概要接口已返回其他维度所需字段、已有未过期缓存或该维度不适用时，跳过重复调用。正常首轮每家公司调用 3–4 个数据类别；完整覆盖专利与软著、中标与资质时，最多消耗 6 个底层工具调用。后续增量更新通常为 1–2 类。批量接口用于减少网络往返；配额消耗按天眼账户实际规则监控。

天眼数据不足的三个核心字段——AI 是否为核心业务、具体 AI 产品、代表性客户案例——继续由官网、政府公告和经审核的行业组织来源补充。

## 5. 评分设计

总分 100 分：

- AI 核心性与产品壁垒：30 分。
- 商业与市场验证：25 分。
- 成长动能：20 分。
- 行业地位：15 分。
- 经营稳定性与透明度：10 分。

### 阶段校准

每项先计算原始证据分，再在相同发展阶段内转为百分位或标准分，最后映射到该项上限。成熟型、成长期和早期公司的阶段得分再进入同一总榜。

阶段划分只使用成立时间、融资/上市状态和规模分档，不使用公司名称或人工偏好。规则版本化保存。若某阶段样本过少，不计算独立百分位，合并到相邻阶段并记录版本说明。

### 缺失与时效

- 核心字段无证据时标记“待补充”，不构成公开负面结论。
- 分项证据覆盖不足时，该公司暂不具备正式排名资格，只进入内部观察池。
- 成长和市场事件以近三年为主要窗口；资质按有效期；风险按发生和解除日期衰减。
- 所有加分、扣分必须关联至少一条证据。

## 6. 用户展示与内部边界

### 用户可见

- 公司名称、发展阶段、AI 赛道和代表性产品。
- 五个评分维度及面向求职者的简短理由。
- 公开市场验证、成长事件、行业资质和风险提示。
- 独立公开证据链接、发布时间和更新时间。
- 数据不足时显示“待补充”。

### 仅内部

- 天眼企业 ID、信用代码哈希和原始响应。
- API 调用状态、额度、失败原因及匹配置信度。
- 供应商字段、中间分、阶段百分位、人工复核记录。
- 抽样层、源行号、工作簿哈希和采集日志。

### 不采集或不保存

- 电话、邮箱、完整地址。
- 法定代表人、董监高个人履历和个人关系图谱。
- 股东穿透关系、司法案件全文。
- 税务、海关、动产抵押等与首版求职目标低相关的数据。
- 天眼评分、商标总量、普通著作权总量和无关知识产权。

## 7. 数据流程与失败处理

1. 用已选 100 家样本的企业全称和信用代码哈希关联本地基线；信用代码原文仅在导入内存中用于供应商查询，不落库。
2. 身份唯一且置信度达标后按缺口执行最多四类调用；歧义企业进入人工复核。
3. 响应先做字段白名单投影，再保存最小化结构化事件和响应哈希。
4. 官网、政府和行业组织证据经域名白名单、robots、身份一致性和内容去重后落库。
5. 证据解析完成后计算阶段校准分和快照。
6. API 认证、限流或额度错误可重试；实体歧义、来源不允许展示或证据不足均失败关闭，不参与正式排名。

## 8. 验收标准

- 100 家样本保持确定性，不因数据补充而改变抽样成员。
- 正常情况下每家公司天眼数据类别不超过四类、底层工具调用不超过六次；已有基线或缓存字段不会重复请求。
- 数据库、日志和 API 响应均不出现被排除的个人敏感字段。
- 每个有效评分项均有证据、时间和来源；缺证据不加分、不扣分。
- 阶段校准测试证明大型成熟公司不会仅凭累计专利或资本规模占优。
- 公共接口不返回天眼原始数据、供应商标识、原始响应或内部评分中间值。
- 内部报告能查看字段覆盖、失败原因、阶段、分项证据和规则版本。
- 首批发布前完成人工抽查，并对高低分及阶段边界样本进行复核。

## 9. 后续扩展边界

未来扩展到其他行业时，复用企业阶段、商业验证、成长、行业地位和稳定性四类通用结构，仅替换行业核心性与技术资产规则。招聘岗位、薪资和岗位趋势属于后续独立模块，不进入本设计的首版评分。
